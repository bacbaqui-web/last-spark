# LAST SPARK 최적화·안정화 적용 기록

2026-10-09. 기준 검토: [최초 진단과 재현 자료](optimization-stability-review-2026-10-09.md).
기존 미커밋 무기·로봇·동작 작업을 보존하고 현재 코드에 수정했습니다. 커밋·원격 배포는 수행하지 않았습니다.

## 진행 데이터와 실행 안정성

- 저장을 읽을 때 프레임·무기·장비·모듈·탄약·단계·결과의 중첩 타입과 범위를 검사합니다. 잘못된 항목을 격리하고 정상 항목은 유지합니다. 빈 프레임과 손상으로 사라진 마지막 무기도 복구합니다.
- 브라우저에서는 정상 저장 백업과 손상 원본을 별도 키에 보존합니다. 용량 부족·접근 차단·다른 저장본과의 충돌을 UI에서 알립니다. 저장 재시도와 JSON 내보내기를 제공합니다.
- 출격과 정비 변경은 저장 실패 시 되돌립니다. 귀환 결과는 메모리에 보존하고 재시도 시 한 번만 반영합니다. 미저장 귀환 결과가 있으면 다음 출격을 막습니다.
- Web Locks 지원 브라우저에서는 같은 저장의 소유 탭을 하나로 제한합니다. 비지원 환경에서는 저장본 비교와 출격 소유권·heartbeat 검사를 사용합니다. 이 fallback은 Web Locks 수준의 원자적 잠금을 보장하지 않습니다.
- 기존 규칙인 출격 중 새로고침/연결 종료에 따른 기체 전손은 유지합니다. 이미 귀환한 창고는 보존됩니다. 런타임 예외의 복구 버튼은 오류 정보를 내보내고 현재 결과로 긴급 귀환합니다.
- Pointer Lock을 얻지 못한 조작 모드에서도 포커스 이탈 시 게임·입력·연속 무기·오디오를 중단합니다. 문서가 숨겨지면 시뮬레이션도 멈춥니다.
- WebGL context loss는 재로드 없이 대기하고, 복구 후 사용자가 재개합니다. RAF는 예외 처리보다 먼저 예약하며, 프레임 예외는 복구 UI로 연결합니다.
- 긴 프레임은 최대 약 16.8ms 단위로 나누고 100ms까지 소비합니다. 정상 플레이 중 250ms를 넘는 멈춤은 일시정지합니다. 원래의 40ms 단순 절삭을 제거했습니다.

## 로딩과 자원 수명

- 적 모델은 격납고 시작을 막지 않고 출격 시 준비합니다. 모델은 동시 2개씩 읽으며, 요청·디코딩에 20초 제한과 기존 모델 fallback이 있습니다. 시작 화면에는 로딩·실패·다시 불러오기 안내가 있습니다.
- 배포 시 로봇 GLB 다섯 개의 동일 atlas를 하나의 외부 이미지로 분리합니다. 원본 GLB·PNG는 수정하지 않습니다. 공통 이미지 분리로 **16,557,654 bytes (15.79MiB)** 절감했습니다.
- 동작 데이터는 Three.js KeyframeTrack이 사용하는 Float32 수치를 그대로 패킹합니다. 원본 JSON은 유지하며, 모든 keyframe 시간·값의 Float32 동등성을 검사합니다.
- ZIP·Blend·PSD 원본은 public에서 dist로 복사하기 전에 제외합니다. 개발 도구 페이지는 계속 빌드합니다.
- 회수 드론의 도색 텍스처는 하나를 공유합니다. 시작 구역에서 제거하는 나무·차량의 소유 자원도 즉시 정리합니다. 기체 PNG 미리보기 캐시는 최근 24개로 제한합니다.
- 사마귀의 긴 팔날이 바닥을 뚫을 때 전신을 올리던 사망 동작을 수정했습니다. 팔 관절을 접어 접촉을 처리하고 실제 형상의 convex hull로 바닥 높이를 계산합니다. hull은 geometry별로 캐시합니다.

## 검증과 배포 방지 장치

`npm test`는 `scripts/verify-*.mjs`를 자동 수집합니다. 누락됐던 검사도 실행하며 실패하면 종료 코드가 0이 아닙니다. 로컬 파일 시스템의 `ECANCELED` 읽기 오류에 한해서 동일 검사를 한 번 재시도합니다. Assertion 실패는 재시도하지 않습니다.

`npm run build` 뒤 `npm run test:release`가 원본 압축 파일 유출, 전체 220MiB, JS 개별 청크 2.2MiB, GLB bufferView 및 외부 이미지 참조를 검사합니다. GitHub Pages 배포도 전체 검사 → 빌드 → 배포 산출물 검사를 통과해야 진행됩니다.

추가 회귀 검사는 저장 손상·저장 실패·귀환 재시도·탭 소유권, 고속 이동·천장, 실제 연결 거리 월드 생성·취소, 정적 메시 병합·GPU 회수, 동작 데이터 동등성, fallback 일시정지·런타임 예외를 다룹니다. 구형 전투 테스트의 간단한 맵은 명시적 test option으로만 선택하며, 기본 월드는 Node와 브라우저 모두 연결 거리 맵입니다.

최종 실행 결과는 `stabilization-evidence-2026-10-09/`에 보관합니다. 원래의 진단 결과는 덮어쓰지 않습니다.

## 실제 확인 결과

- 전체 자동 검사 **56/56 통과**. 이후 브라우저에서 발견한 “이미 일시정지한 뒤 context loss”의 안내 유지 문제를 추가 수정하고 `verify-salvage-runtime`에 재현 검사를 넣어 다시 통과했습니다. Pointer Lock 해제·blur가 오류 복구 버튼을 덮어쓰지 않는 조건도 검사합니다.
- 프로덕션 빌드와 배포 산출물 검사 통과. 파일 바이트 합계 기준 기존 **279,350,299 bytes (266.41MiB)**에서 **151,073,841 bytes (144.08MiB)**로 줄었습니다(약 46% 감소). 이전의 디스크 점유량 `du` 수치와 혼용하지 않았습니다. 원본 ZIP 제외는 배포 총용량 개선이며 초기 화면 다운로드가 그만큼 줄었다는 뜻은 아닙니다.
- Apple M4 / 16GiB / Codex 앱 브라우저 / 1280×720에서 최종 배포 빌드의 격납고 → 브리핑 → 출격 → 이동·연속 사격 → 귀환·결과 저장을 확인했습니다. 별도 포트 5196의 새 저장을 사용했습니다.
- 격납고와 브리핑의 게임·무기 draw call은 **모두 0**. 브리핑까지 적 GLB 요청도 **0**입니다. 귀환 뒤에도 두 패스 모두 0으로 돌아갑니다.
- 같은 시드 `3040804531`, STAGE 1의 적은 **계획한 5체**(일반 4 + 보스 1)입니다. 기존 측정에서는 배치 실패로 3체였습니다.
- 공통 atlas의 실제 본문 전송은 한 번(4,139,122 bytes)이었습니다. 나머지 요청 네 번은 본문 없는 캐시 재검증(각 전송량 300 bytes)이었습니다. 이는 다운로드 중복 제거 근거이며 GPU texture 객체를 하나로 통합했다는 측정은 아닙니다.
- 예열 후 최근 600프레임: 평균 **16.72ms**, p95 **17.4ms**, p99 **17.6ms**, CPU update **3.39ms**, render submission **5.84ms**. 메인 1,080 calls, 무기 5 calls. 자동 DPR은 0.85였습니다. 기존 측정과 적 수·위치·DPR이 달라 엄밀한 속도 개선율로 해석하지 않습니다.
- 두 번째 탭에서는 저장 소유권 안내와 출격 비활성화를 확인했습니다. 포커스 이탈은 조작 모드 fallback에서도 정지했습니다. `WEBGL_lose_context`로 손실·복구를 주입하여 복구 안내, 수동 재개, 진행 유지와 귀환을 확인했습니다. 이동 6m와 기관총 7발 소모를 실제 화면에서 확인했습니다.
- 검사 구간의 콘솔 오류·경고는 없었습니다. 임의의 오류를 주입하는 자동 검사와 의도적인 context loss는 정상 상황의 오류율에 포함하지 않았습니다.

## 해석 범위

- 최초 heap 수치는 다른 작업·GC 상태가 섞인 수치입니다. 새 구조와의 수치를 누수율이나 엄밀한 속도 배율로 표현하지 않습니다.
- p95/p99는 최근 600프레임의 CPU 관측 지연이며 GPU 실행 시간을 직접 측정한 값은 아닙니다. 게임과 무기 패스의 그리기 수를 별도로 표시합니다.
- 구역 단위 생성은 내부의 모든 작업을 8ms 이하로 제한하는 Worker 구현이 아닙니다. 먼 구역은 GPU 자원을 회수하지만 CPU 형상까지 폐기하는 완전한 스트리밍은 적용하지 않았습니다. 충돌 정확성과 귀환 시 상태 보존을 우선했습니다.
- 렌더러 통합, 모든 무기의 지연 생성, KTX2/Draco 전환은 적용하지 않았습니다. 원래 제안의 조건부 구조 변경을 무리하게 한 번에 도입하지 않고, 확인된 낭비와 오류를 먼저 제거했습니다.
- 30분 연속 전투·30회 실제 출격·100회 장비 교체, Safari/Firefox/Edge와 저사양 GPU, 실제 절전/복귀의 전체 조합은 별도 실기 검증이 남습니다. 현재 확인 범위를 넘어 모든 환경의 안정성이나 일정 FPS를 보장하지 않습니다.
