# 원거리 지도 모델 단순화

## 동작

- 가까운 모델은 원본을 사용합니다. 카메라에서 모델 경계까지 32m부터 중간 단계, 65m부터 원거리 단계로 전환합니다. 복귀 경계에 3m의 여유를 두어 경계에서 반복 전환하지 않게 했습니다.
- 건물은 같은 창문 텍스처와 큰 외벽·층 높이·붕괴 윤곽을 유지하고, 중·원거리에서 벽돌 단면, 작은 잔해, 난간, 실내 세부 구조를 줄입니다. 수정된 별도 파손 모델은 원본을 유지합니다.
- 나무는 중거리에서 주요 가지와 잎 묶음, 원거리에서 단순 줄기와 큰 잎 카드만 사용합니다. 부러진 나무에 새 잎이 생기지 않으며 접근하면 원본 형상을 복구합니다.
- 반복 배치된 작은 잔해는 중거리에서 3개 중 1개, 원거리에서 10개 중 1개를 표시합니다. 카메라가 가까워지면 원래 인스턴스와 순서가 복구됩니다.
- 가까운 건물의 동일한 형상·재질은 구역별 인스턴스로 함께 그립니다. 중·원거리 건물은 모양이 달라도 같은 재질끼리 합치고, LOD가 바뀔 때만 그릴 삼각형 인덱스를 갱신합니다. 회전·크기·이끼 투영을 보존하며 음수 배율 모델은 기존 메시 경로를 사용합니다.
- 정적 재질을 비교할 때 텍스처 이미지를 PNG로 다시 인코딩하지 않고 텍스처 참조만 비교합니다. 지도 준비 중 불필요한 이미지 변환과 메모리 할당을 제거했습니다.
- 충돌과 총알/시야 검사용 BVH는 단순화 전에 만든 원본 형상을 계속 사용합니다. 표시 단계가 바뀌어도 원본 충돌 형상과 좌표를 바꾸지 않습니다.

## 모델별 삼각형

실제 도로 모델의 표본입니다. 가까이/중간/멀리의 동일 모델을 같은 배율로 렌더링했습니다. 모델의 삼각형 수이며 FPS 개선율이 아닙니다.

| 모델 | 근거리 | 중거리 | 원거리 | 근거리 대비 원거리 감소 |
|---|---:|---:|---:|---:|
| 도로 나무 0 | 3,284 | 736 | 130 | 96.0% |
| 벽돌 주택 2 | 10,368 | 525 | 161 | 98.4% |

20종 건물 모두 원거리 90% 이상, 10종 나무 모두 원거리 95% 이상 감소 조건을 통과했습니다. 모든 기존 근거리 모델 30종의 위치·노멀·색상·UV 배열을 변경 전과 바이트 단위로 비교해 동일함을 확인했습니다.

## 검증

`scripts/verify-street-model-lod.mjs`는 거리 전환과 복귀, 경계 여유, 원본 복구, 동결된 좌표, 회전/축별 배율, 총알 판정 315건, 부러진 나무, 잔해 재배치, 인스턴스의 실제 월드 좌표와 그리기 요청 감소, 재질 비교 시 이미지 변환을 하지 않는 조건을 검사합니다. `verify-static-batching.mjs`는 기존 정적 병합과 먼 구역의 GPU 자원 해제를 계속 검증합니다.

비교 이미지와 원시 측정은 `output/distant-lod/`, 밀집 전투 결과는 `output/crowd-performance/summary-lod-*.json`에 보관합니다. 개인 브라우저나 실제 캠페인 저장을 사용하지 않은 격리 Chrome에서 검사했습니다.

최종 코드에서 `npm test` 71/71, `npm run build`, `npm run test:release`를 통과했습니다. 실제 모델 비교 화면의 이미지 6개와 표면/삼각형 전환, 1100·736·320px 화면에서 잘림 없는 배치도 브라우저에서 검증했습니다.

## 성능 해석

회수작전 시드 3040804531, Apple M4, 1280×720, DPR 1, 균형 화질에서 비교합니다. 적 80/120마리를 고정하고 같은 입력으로 3초 준비 후 8초씩 측정하며, 맵 자체의 그리기 작업은 적과 드롭을 제거한 네 지점에서 따로 비교합니다.

건물별로 단순히 모델을 교체한 첫 구현은 삼각형은 줄었지만 그리기 요청이 증가했습니다. 따라서 근거리에는 구역별 건물 인스턴스, 중·원거리에는 재질별 형상 병합을 추가했습니다. 밀집 전투는 AI·관절·충돌 계산의 영향도 받으므로 삼각형 감소만으로 60 FPS나 같은 비율의 FPS 향상을 보장하지 않습니다.

### 최종 코드의 실제 장면 비교

최신 적 기체·이동 코드를 양쪽에 동일하게 적용하고 지도 관련 모듈만 교체해 비교했습니다. 네 카메라 위치의 맵 장면 렌더 통계입니다. 그림자와 남아 있는 무기 표시가 포함될 수 있으므로 순수 모델 원본 삼각형 합계와는 다릅니다.

| 경로 진행 위치 | 변경 전 삼각형 | 변경 후 삼각형 | 감소 | 변경 전 → 후 그리기 요청 |
|---|---:|---:|---:|---:|
| 시작점 | 1,051,228 | 467,245 | 55.6% | 551 → 363 |
| 25% | 1,425,728 | 666,911 | 53.2% | 622 → 446 |
| 50% | 1,486,706 | 652,929 | 56.1% | 679 → 473 |
| 80% | 820,468 | 684,231 | 16.6% | 354 → 375 |

단일 8초 밀집 전투 측정은 아래와 같습니다. 짧은 로컬 측정이며, 원경 삼각형 감소가 확인되어도 밀집 전투 FPS 개선은 확인되지 않았습니다. 특히 CPU 업데이트 시간이 지배적이어서 이 결과를 FPS 향상으로 표현하지 않습니다.

| 적 수 | 변경 전 → 후 평균 FPS | 변경 전 → 후 업데이트 시간 | 변경 전 → 후 렌더 제출 시간 |
|---|---:|---:|---:|
| 80 | 38.2 → 26.8 | 16.3 → 25.6ms | 8.8 → 10.5ms |
| 120 | 18.8 → 16.5 | 41.0 → 48.1ms | 11.0 → 11.4ms |

원시 파일: `summary-lod-release-before.json`, `summary-lod-merged-after.json`, `map-lod-release-before.json`, `map-lod-merged-after.json`. 두 브라우저 실행 모두 런타임 오류가 없었습니다. 이 변경은 원경의 삼각형과 대다수 장면의 그리기 요청을 줄이지만 밀집 전투 성능 문제의 해결 완료로 보지 않습니다.

추가 CPU 프로파일에서 거리별 건물 갱신은 6초 캡처 중 약 1.3ms였고, 적 관절 좌표 갱신·적 렌더 처리·이동 충돌 검사가 큰 비중을 차지했습니다. 프로파일은 별도 실행으로 수집했으며, 이 수치를 위 FPS와 직접 합산하지 않습니다.
