# 진행 중 성능 저하·이동 속도·초기 적 배치 수정

> 아래 앞부분은 첫 수정 당시의 기록입니다. 최신 조작/배치는 `walk-density-2026-10-09.md`, 시야 기반 처리의 후속 변경은 이 문서 마지막 절을 참고합니다.

요청: 시간이 지날수록 느려지는 현상, 너무 빠른 이동, 비어 보이는 시작 구간을 개선했습니다. 기존 변경 파일은 유지했습니다.

## 확인한 원인과 수정

- 로봇 제거가 `cosmetic` 형상과 총구 섬광에만 한정되어, 드론의 실린더 형상·전용 재질·일부 적의 피격 판정 메시가 GPU에 남았습니다. 반대로 모든 로봇이 공유하는 골반 형상은 개체를 제거할 때 함께 해제됐습니다.
- `runtime-resources.js`에서 개체 소유 형상·재질·스켈레톤을 중복 없이 정리합니다. 공용 형상·재질과 승인 에셋 템플릿은 보존하고, 복제한 형상은 개체가 소유하도록 표시합니다. `disposeRobot`은 중복 호출해도 안전합니다.
- 먼 적도 매 프레임 순찰 충돌·발 위치·시야·애니메이션을 계산했습니다. 대기 중인 적은 72m 밖에서 갱신을 멈추고, 교전 중인 적은 110m까지 추격을 유지합니다. 접근하면 즉시 다시 갱신합니다. 130m 밖에서는 표시하지 않습니다.
- 전리품의 600초 수명과 획득 데이터는 유지합니다. 50m 밖의 모델, 30m 밖의 빛 기둥을 숨기고 가까운 드롭만 회전·부유시킵니다.
- `performanceStatus()`에 활성 적, 사망 연출, 보이는 드롭, 발사체, 효과, 음성, 셰이더 수를 추가했습니다.

## 조작과 배치

- 기본 이동 값 10.8 → 6.8m/s, 약 37% 감소. 일반 출격의 기존 ×0.85 보정을 적용하면 약 5.78m/s입니다. 정밀 조준 이동 값 2m/s는 유지합니다.
- 일반 대시 값 30 → 22. 특수 칼 돌진의 공격 동작은 유지합니다.
- 연결 도로의 첫 그룹은 경로 26m 지점 주변에 3마리, 시작 지점과 최소 18m를 띄웁니다. 이후 약 72m마다 추가 그룹을 배치합니다.
- 335m STAGE 1은 일반 적 9마리와 수호 개체 1마리입니다. 기존에는 일반 적 4마리와 수호 개체 1마리였습니다. 지형 때문에 후보 위치가 막혀 있으면 안전한 위치를 재탐색합니다.

## 후속: 시야 밖 적과 정적 맵의 계산 중단

사용자가 화면 밖 렌더링 및 보이지 않는 적의 이동 중단 여부를 질문하며 심한 지연을 보고했습니다. 확인 당시 Three.js의 메시 단위 시야 절두체 검사는 있었지만, 적 AI는 주로 72/110m 거리로만 제한됐습니다. 또한 `visible=false`와 `matrixAutoUpdate=false`만으로는 하위 개체의 `updateMatrixWorld` 순회를 막지 못했습니다.

- 원격 출격의 적은 카메라 시야 구 밖이거나 벽에 완전히 가려지면 AI·이동·애니메이션·뼈대 좌표 갱신과 표시를 멈춥니다. 다시 보이면 현재 상태에서 재개하며, 쉬었던 시간을 몰아서 진행하지 않습니다. 체력/불 피해/사망/보상 처리는 유지합니다.
- 몸통·머리·양 어깨의 노출을 검사해 일부가 보이는 적을 잘못 숨기는 일을 줄입니다. 벽 검사는 0.2초 캐시를 쓰며 카메라나 적이 1m 이상 움직이면 다시 검사합니다. 시야 밖에서 안으로 돌아오는 검사는 즉시 갱신합니다. 완벽한 픽셀 단위 가림 판정은 아닙니다.
- 맵은 거리와 블록 경계 상자의 카메라 시야 검사를 함께 사용합니다. 보이지 않는 블록의 생물/불 연출 갱신을 건너뜁니다. 벽 뒤 정적 맵 전체에 대한 가림 판정까지 추가한 것은 아닙니다.
- 생성 후 변하지 않는 건물·도로·나무의 월드 좌표를 한 번 계산해 고정했습니다. 원본 충돌 데이터는 유지하고 운송 드론 및 추락지 동작은 갱신합니다. 무기 렌더링 때 씬 전체 좌표를 다시 계산하던 중복 경로도 제거했습니다.
- 진단에 보이는 적, 가려진 적, 시야 검사 횟수, 고정한 정적 개체 수를 추가했습니다. 총 적 수와 걷기/Shift 달리기 설정은 유지합니다.

## 추가 후속: 그림자 재사용과 이끼 표면 배칭

추가 성능 개선 요청에 따라 다음 경로를 줄였습니다.

- 같은 재질을 공유하는 정적인 이끼 표면을 묶습니다. 월드 좌표를 사용하는 것으로 확인한 이끼 셰이더만 허용하고, 재질 객체가 다르면 강도/유니폼을 섞지 않습니다. 좌표와 법선을 미리 변환하며 충돌 원본을 보존합니다. 모두 묶인 원본 하위 그룹 204개는 렌더 순회에서도 제외됐습니다.
- 자동/균형 화질의 그림자 깊이 맵은 최대 20Hz로 갱신하고 중간 프레임에는 재사용합니다. 카메라·입력·전투·애니메이션의 프레임률은 제한하지 않습니다. 화질 우선은 최대 60Hz입니다. 광원 위치, 맵/구역 가시성 변경, 재시작, 그래픽 복구 시 즉시 갱신합니다. 움직이는 그림자의 부드러움과 렌더 비용 사이의 선택입니다.
- 투명 무기 캔버스는 도시/적/효과 전체를 다시 순회하지 않습니다. 카메라 자식과 조명만 그리며 이 패스의 별도 그림자 계산을 끕니다. 원래 씬 상태는 렌더 오류가 나도 복원합니다.
- 자동 화질의 초기 pixelRatio 상한을 1.25 → 1로, 과부하 대응 간격을 최소 10초 → 3초로 줄였습니다. 회복은 10초 간격으로 천천히 처리합니다. 무기 캔버스는 최대 1배 해상도입니다. 아래 성능 비교는 균형 화질·pixelRatio 1로 진행하여 자동 해상도 감소 효과를 섞지 않았습니다.

### 로딩을 제외한 실제 비교

같은 1280×720 브라우저, 시드 3040804531, 균형 화질, 정지 상태에서 게임 시간 2초에 통계를 초기화하고 6초까지 측정했습니다. 이전 절의 최초 준비/착륙을 포함한 수치와 직접 비교하지 않습니다. 난수 초기값도 맞췄지만 프레임 진행에 따른 적 행동/자폭은 달라 전후 종료 시 적은 34/35마리였습니다. 전투 상태가 완전히 동일한 결정론적 벤치마크는 아닙니다.

| 항목 | 이번 수정 전 | 이번 수정 후 |
|---|---:|---:|
| 측정 프레임 수 | 239 | 240 |
| 평균 렌더 명령 처리 | 4.735ms | 3.400ms |
| 평균 프레임 간격 | 16.736ms | 16.667ms |
| 프레임 시간 95백분위 | 17.3ms | 17.4ms |
| 측정 중 가장 긴 프레임 | 33.3ms | 17.7ms |
| 종료 시 그리기 호출 | 1,119 | 691 |
| 종료 시 GPU 형상 수 | 1,440 | 942 |

렌더 명령 처리 평균은 약 28%, 종료 시 그리기 호출은 약 38% 줄었습니다. 95백분위는 사실상 비슷했고, 짧은 측정 구간에서 60Hz 표시 주기를 유지했습니다. 그리기 호출은 종료 시점 비교이며 GPU 전체 처리 시간이나 장시간 FPS 보장 수치는 아닙니다. 브라우저 오류 로그는 비어 있었습니다. 원본: `output/render-budget/browser-before.json`, `browser-after.json`, `gameplay.jpg`.

8개 관련 검사(그림자/무기 패스/화질, 정적 배칭, 원격 출격, 화염/칼/입력, 3인칭, 레이저/활, 연결 맵, 적 시야)와 빌드/배포 산출물 검사 통과. 60Hz에서 600프레임 동안 그림자를 200번만 갱신하는 검사, 오류 후 씬 복원, 재질 강도 구분, 변환/충돌 보존을 포함합니다. 결과는 `output/render-budget/`에 보관합니다. 빌드 283파일 / 144.081MiB이며 로컬 반영까지 수행했습니다.

사용자 요청: 더 강한 최적화를 계속 진행. 이번에는 실제 전투 경로, 반복 생성되는 시각 효과, 사망 물리, 미회수 전리품, 조명 변경에 따른 셰이더 준비 비용을 수정했다.

### 적용 내용

- `combat-effects.js`: 탄피 48개, 총구 불꽃 128개, 탄도선 64개를 상한으로 재사용한다. 탄피/불꽃의 도형과 재질도 공유한다. 상한은 시각 효과에만 적용되며 실제 탄환의 피해 계산을 생략하지 않는다. 초기화 시 사용 중인 효과는 모두 반납하고, 재사용용 자원은 한도 내에서 유지한다.
- `main.js`: 화염이 없는 프레임에도 실행되던 전체 장면 좌표 갱신을 제거했다. 사격에 필요한 카메라/적의 좌표만 갱신하며, 위치 기반 폭발/근접 판정에서는 불필요한 전체 순회를 제거했다. 광선 무기의 중복 좌표 갱신도 제거했다.
- `street-walk-collision.js`: 기존 공간 분할을 유지하고, 가장 가까운 벽만 필요한 광선은 그 벽 뒤 구역의 탐색을 종료한다. 중복 후보 추적에 사용하던 매번 생성되는 Set도 재사용 가능한 방문 표식으로 교체했다. 축척이 다른 모델의 near/far 범위와 물체 안에서 시작한 광선도 검사했다. 적 시야, 조준 보정, 3인칭 카메라에도 적용했다.
- `death-budget.js`: 화면 밖/90m 밖 사망 연출은 즉시 자원을 정리한다. 화면 안의 복잡한 사망 연출은 동시에 최대 6개이며, 초과분은 짧은 축소 연출로 마무리한다. 보상/드롭/처치 횟수는 기존 게임 처리 후 별도로 확정되므로 이 제한의 영향을 받지 않는다.
- `wild-enemy-debris.js`, `wild-enemy-destruction.js`: 물리 상태 저장·보간에서 임시 벡터/배열 생성을 줄였다. 잘게 부서진 파편으로 교체된 뒤에는 보이지 않는 이전 몸체의 물리를 더 진행하지 않는다. 연기 발생 위치는 한 번만 계산한다. 도구의 되감기, 고정 물리 간격, 30/60fps 재생 일치 검사는 유지했다. 물리 안정화 검사는 파편으로 교체된 뒤 실제 보이는 파편을 확인하도록 바꿨다.
- `combat-budget.js`: 미회수 전리품은 삭제하지 않는다. 시야 안 가까운 32개만 상세 모델을 표시하고, 30m 안에서는 다른 아이템도 종류별 색상 표식으로 남긴다. 숨긴 전리품은 하위 좌표 순회와 부유 애니메이션도 중단한다. 획득 판정과 수명은 유지한다.
- `combat-lights.js`: 적의 총구/파괴 조명은 항상 존재하는 4개 조명 슬롯 중 영향이 큰 순서로 재사용한다. 빈 슬롯은 밝기 0을 유지한다. Three.js가 조명 개수를 셰이더 캐시 키에 포함하므로, 적이 나타나거나 죽을 때마다 조명 개수별 셰이더를 다시 준비하는 비용을 줄인다. 총구 불꽃/불/연기 자체는 남는다.

## 추가 후속: 훈련장의 누락된 계산 제한과 반복 UI 갱신

두 게임모드 도입 후 추가 점검에서 확인한 항목입니다.

- **훈련장에는 적/전리품 제한이 빠져 있었습니다.** 회수작전에만 걸린 `salvageMode` 조건 때문에 훈련장에서는 화면 밖 로봇도 계속 AI·자세를 갱신했고, 가까운 전리품의 전체 모델을 모두 표시했습니다. 훈련에도 시야/가림 검사, 정지·재개, 32개 상세 모델 상한을 적용했습니다. 수송선에서 하강 중인 적은 진입을 완료한 뒤 휴면 처리하므로 웨이브가 멈추지 않습니다. 물체 표시와 아이템 획득은 별개로 유지됩니다.
- **공격 기능이 없는 등 장비도 매 프레임 적과 장애물을 탐색했습니다.** 일반 기체·제트팩·방어막에는 표적 탐색을 수행하지 않습니다. 자동 사격 장비도 재사용 대기 중에는 탐색을 생략합니다. 방어막 회복과 사냥개 이동, 발사 간격/에너지 비용은 유지합니다.
- **탄약 1발마다 무기 슬롯의 SVG/HTML을 통째로 다시 만들었습니다.** `weapon-slot-hud.js`에서 장착 무기가 바뀔 때만 구조를 만들고, 사격·보급·무기 전환은 숫자·호·선택 상태만 갱신합니다. 탄창 240발을 소모하는 동안 슬롯 노드가 같은 객체로 유지되는지 검사했습니다.

## 추가 후속: 적 관절 계산과 정비실 대기 비용

이번에는 적의 모습·행동 빈도를 유지하면서 관절 계산의 중복 작업과 정비실의 불필요한 렌더링을 줄였습니다.

- **적 다리 관절 계산**: 역운동학의 매 반복마다 전체 몸체·장식 메시와 상위 계층을 다시 계산하던 경로를 제거했습니다. 변경된 관절부터 발끝까지 필요한 좌표만 갱신하고, 자세가 완성된 뒤 전체 모델에 반영합니다. 반복 횟수, 발 목표 위치, 보행 속도, 무기 조준·공격 동작은 유지합니다. 임시 목표 벡터·역행렬·회전 객체도 재사용합니다.
- **정비실 요청 시 렌더링**: 기체 선택 회전·마우스 드래그 중에만 연속으로 그립니다. 정지한 화면은 렌더링과 자체 애니메이션 프레임 예약을 멈춥니다. 창 크기 변경, 숨겨진 화면의 복귀, UI 호스트 교체, WebGL 복구 시 다시 그립니다. 회전은 충분히 가까워지면 목표 각도에 정확히 도달하도록 하여 끝없이 예약되지 않게 했습니다.
- **기체·창고 모델 재사용**: 선택·이름·체력 변경으로 전체 모델을 다시 만들지 않습니다. 창고 무기와 기체 장착 상태의 변경 감지도 분리했습니다. 실제 외형이나 무기 종류가 달라지면 해당 영역을 갱신합니다. 정비 UI가 사용하지 않던 별도 미리보기 이미지 생성도 제거했습니다.
- **자원 정리**: 제거한 무기·거치대의 전용 재질과 geometry를 함께 해제합니다. 공통 정리 함수가 `sharedSalvageMaterial`로 표시한 기체·장비 재질을 해제하던 문제도 수정했습니다. 살아 있는 다른 기체의 공유 자원을 보존하고, 정비실 종료 시 장면·조명·observer·렌더 예약을 정리합니다.

## FPS 표시와 다수 적 부하 시험

전투 화면 오른쪽 위에 작은 `60 FPS` 형태의 표시를 추가했습니다. 실제 게임 루프의 프레임 간격으로 평균을 계산하여 0.5초마다 갱신합니다. 숫자가 같으면 DOM 텍스트를 다시 쓰지 않고, 마우스 입력을 가로채지 않습니다. 일시정지·메뉴·숨겨진 탭에서는 숨기고 측정 구간을 초기화합니다. 정비실은 필요할 때만 그리므로 FPS 표시 대상에서 제외합니다.

### 시험 조건

`scripts/profile-enemy-crowds-browser.mjs`로 별도 Chrome 프로필에서 실제 게임 루프·시간 분할·AI·총격·충돌·WebGL을 실행했습니다. 회수작전 저장소는 메모리 전용이며 개인 저장 데이터는 사용하지 않았습니다. **1280×720, 균형 화질, pixelRatio 1**입니다. 성능 시험 중에는 다른 회귀 검사나 빌드를 실행하지 않았습니다.

- 각 모드에 척후병·사마귀·딱정벌레·저격 거미·드론을 섞어 **40/80/120/200마리**를 배치했습니다. 보스는 제외했습니다. 전리품 80개에서 시작하고 플레이어는 무적·무제한 미니건으로 계속 사격했습니다. 음향은 활성화하지 않았습니다.
- 고정 부하는 위치·체력을 매 시뮬레이션 단계 되돌려 적 수와 밀집도를 유지합니다. AI/관절/적의 공격/총격 효과는 실제 코드대로 실행합니다. 초기 3초 후 **20초씩 측정**했습니다. 일반 이동 전투 전체를 재현한 조건은 아닙니다.
- 별도로 각 모드에서 **120마리를 유지하는 60초 연속 전투**를 실행했습니다. 이때는 이동·피해·사망·전리품을 허용하고 죽은 적을 보충합니다. 일반 훈련장 웨이브 상한인 일반 적 40마리+보스보다 큰 과부하 조건입니다.
- `1% low`는 가장 느린 1% 프레임의 평균 시간에서 환산했습니다. 평균 FPS는 전체 프레임 간격의 평균으로 계산했습니다. 고정 부하와 연속 전투 모두 실제로 활성화된 적 수를 함께 기록했습니다.

## 추가 진단: 회수전을 진행할수록 느려지는 이유

이번 변경은 진단 스크립트와 기록에 한정한다. 실제 게임의 물리·전리품·전투 규칙은 변경하지 않았다. 기존 고정 위치 시험에 CPU 프로파일을 추가하고, 실제 회수전 배치로 도로를 이동하는 시험을 별도로 실행했다. 개인 저장 데이터 대신 메모리 캠페인과 별도 Chrome 컨텍스트를 사용했다.

### 확인한 주요 병목

1. **사망 후 분해 물리**: `wild-enemy-debris.js`는 1/180초 고정 간격, 물리 해법 최대 40회 반복을 사용한다. `death-budget.js`가 상세 연출을 6개까지 제한하지만 각 개체의 관절·파편 비용이 크다. 120마리 유지/연속 사격/25초의 CPU 표본에서 사망 갱신 경로가 전체 측정 시간의 **35.3%**를 차지했다. 살아 있는 적 애니메이션은 **14.6%**, 렌더 명령 제출은 **19.1%**였다. 각 경로의 하위 함수를 더하면 중복 계산되므로 상위 경로 수치만 비교했다.
2. **느린 프레임에서 계산 반복**: `runtime-performance.js`의 `frameSteps`는 최대 100ms를 6개로 나눠 게임 전체를 갱신한다. 프레임이 길어지면 한 번 그리는 동안 AI·충돌·사망 연출도 여러 번 호출되므로 CPU 부하가 더 커질 수 있다. 파편 물리는 이와 별도로 180Hz 간격을 따라간다.
3. **보존되는 전리품과 후반 추가 적**: 전리품은 회수전에서 600초 유지되고, 상세 렌더링 32개 제한과 별개로 전체 획득·가시성·수명 검사가 수행된다. 코어 회수 시 귀환 매복 적도 추가된다. 다만 이번 120마리 프로파일의 전리품 획득+표시 검사는 합계 약 70ms/25.55초로 **0.3% 미만**이었다. 이번 병목의 주범으로 해석하지 않는다. 초기 도로 적은 출격 때 전체 배치되며, 이동할수록 무조건 계속 생성되는 구조는 아니다.

화면 밖 적의 휴면·시야 밖 맵 숨김은 이미 작동한다. 보이는 사망 연출의 물리와 살아 있는 적의 애니메이션 비용은 별도다. 화면 해상도만 낮춰도 해결된다고 볼 수 없다.

### 사망 물리 비교 시험

1280×720, DPR 1, 균형 화질, 회수전 120마리를 계속 보충하며 25초 연속 사격했다. 양쪽 모두 CPU 프로파일을 켰다. 시험용 Vite 변환에서만 `maxDetailed=0`으로 바꿔 짧은 축소 사망 연출을 사용했다. 배포 게임에는 적용하지 않았다. 프레임 수에 따라 난수 소비·처치 시점이 달라지므로 완전히 동일한 전투 재생은 아니다.

### 실제 배치로 도로 진행

`scripts/profile-recovery-route-browser.mjs`는 335m 도로의 실제 초기 배치 **35마리**를 사용했다. 110초 동안 경로를 초당 4.2m로 자동 이동하고 가까운 적을 조준·사격했다. 무적·무한 탄약·배터리 보충을 사용했고 소리는 비활성 상태다. 실제 게임의 RAF/시간 분할/처치/전리품 획득은 유지했지만 수동 조작과 동일한 재생은 아니다.

- 34마리 처치, 끝 지점까지 이동. 수호 개체 1마리가 남아 코어 회수·귀환 매복은 시험하지 못했다.
- 게임 시간 10~70초의 10초 구간별 평균은 **53.7~58.9FPS**, 긴 프레임은 최대 **199.9ms**였다. 70초 이후에는 약 **60FPS**로 회복했다. 계속 낮아지는 추세는 이 시험에서 재현되지 않았다.
- CPU 표본의 게임 `update` 하위 총 23.36초 중 사망 갱신이 16.26초, 약 **69.6%**였다. 전체 측정 시간 대비로는 14.7%이며, 나머지에는 렌더링과 대기 시간도 포함된다.
- 전리품은 최대 16개/종료 14개, 사망 연출은 최대 5개/종료 0개였다. JS 힙 표본은 약 452~529MB에서 오르내렸고, 시작 약 470MB/종료 약 458MB였다. GPU 형상은 583→최대 1,956→종료 1,735개, 텍스처는 55→84개였다. 새 구역·사망 연출·전리품의 자원 등록과 보존이 있어 GPU 수가 증가하지만, 이 수치만으로 무한 누수라고 할 수 없다. JS 힙만으로 GPU 메모리 누수 부재도 증명할 수 없다.
- 초기화 중 이미 대기하던 RAF 시각 때문에 원본의 첫 두 표본은 음수 elapsed/게임 시간 0을 포함한다. 구간 결과는 게임 시간 0과 음수 표본을 제외하고, 실제 플레이 중 긴 프레임은 모두 유지했다. 후속 스크립트는 같은 초기 표본을 수집하지 않는다.
- JavaScript/콘솔 오류 0건. 원본·프로파일·화면·구간 집계는 `output/recovery-route-performance/diagnosis*`에 보관했다.

따라서 확인된 우선 개선 대상은 게임 중 사망 물리 비용, 그다음 생존 적 애니메이션·그리기 호출과 프레임당 반복 갱신이다. 사용자 환경의 수십 분 진행, 코어 회수 후 귀환, 소리 활성화까지의 지속 저하 원인은 아직 확정하지 않았다.

재현: `CROWD_PROFILE=1`로 CPU 기록, `CROWD_DEATH_DETAIL=simple`로 시험용 사망 비교를 켠다. `ROUTE_PROFILE=1 node scripts/profile-recovery-route-browser.mjs`로 진행 시험을 실행한다. 두 시험 모두 `PLAYWRIGHT_MODULE` 경로를 지정할 수 있으며, 전용 포트 5188을 사용하므로 동시에 실행하지 않는다. `node scripts/summarize-cpu-profile.mjs <file.cpuprofile>`은 호출 경로 중복을 제거한 함수별 CPU 요약을 출력한다. 3개 진단 스크립트 문법 검사와 실제 브라우저 실행을 통과했다. 게임 소스 변경이 없어 전체 회귀/빌드는 다시 실행하지 않았다.

## 적 사망 연출을 검은 파츠 흩어짐으로 교체

사용자가 복잡한 사망 연출 대신 즉시 터지며 검은 파츠만 사방으로 흩어지는 동작을 요청했다. 앞 절의 진단 후 실제 게임에 적용한 변경이다.

- `enemy-death-burst.js`: 기존 모델의 보이는 기계식 파츠를 그대로 재사용한다. 모든 파츠는 처음부터 검은 단일 MeshBasicMaterial이며, 텍스처·발광·그림자를 사용하지 않는다. 살아 있는 다른 기체의 재질이나 형상은 변경하지 않는다. 숨겨진 무장·투명 충돌 프록시는 파츠로 만들지 않는다.
- 절대 시간으로 포물선 이동과 회전만 계산한다. 180Hz 물리, 관절/접촉 반복, 파편 추가 분할, 과거 자세 저장을 제거했다. 초기 포즈와 변환을 보존하며 벽면 적·축소 드론·대형 보스의 중력도 월드 아래 방향으로 작용한다. 충돌·바운스 없이 1.05초 후 정리된다.
- 모든 적이 같은 방식으로 터진다. 화면 밖/90m 밖 연출은 정리하고, 동시에 6개를 넘는 상세 연출은 12개 대표 파츠·0.55초로 제한한다. 초과 시에도 검은 파츠가 흩어지는 형태를 유지한다.
- 사망 불꽃·연기·전기·폭발 구체·동적 조명을 제거했다. 짧은 폭발 소리 1회는 유지한다. 자폭형 적도 같은 파츠 연출을 쓰며 자폭 피해 판정은 유지한다. 무기의 기존 발사/명중 효과, 처치 보상, 플레이어 사망 카메라 동작은 유지한다.
- 모델 작업실의 파괴/피격 파괴/다시 재생/슬로 모션과 설명을 새 동작에 맞췄다. 이전 파괴 물리 모듈은 게임의 import 경로에서 제거됐다.

### 검증
